# MacGPT 개별 사실 학습 — 원문 한 번 입력, 사실별 독립 검토·저장

기존 12건 제한과 12건 단위 승인 묶음, 그리고 여러 사실을 한 승인 항목에 합치는 방식을 사용하지 않습니다.

- **한 문장·개별 사실 = 변경안 1행 = 승인 후 지식 1행.** 복잡한 문장은 기계적으로 보수적으로 나누어 작성하므로 일부 복합 주장은 수동 검토해야 합니다.
- 한 번 입력한 문서에서 수백 건의 사실이 나오더라도 **각 사실마다 독립된 승인·거절 버튼, 별개 UUID·수정·폐기 이력**을 가집니다.
- Supabase `knowledge_learning_sources`에 원본 텍스트·SHA256·업로드자 보관. 각 변경안에는 출처 UUID·원문 발췌·문맥·오프셋 기록. 실제 지식으로 저장되는 정보는 검토한 사실뿐입니다.
- 서버가 `create_atomic_learning_proposals`라는 트랜잭션 SQL 함수로 원본과 다수의 개별 변경안 행을 함께 저장합니다. 잘못된 항목이 하나라도 있다면 SQL 전체가 실패하며 부분 생성하지 않습니다.
- `/proposals`는 **25개씩 페이지 이동**하고 전체 건수는 제한하지 않습니다. 승인한 지식은 개별 ID로 수정/폐기할 수 있습니다. 새 학습 결과는 채팅의 링크를 통해 승인 페이지에서 확인합니다.
- 제목·목차·문맥 등 사실이 아닌 원문의 영역은 출처에 보관합니다. 원문 모든 문자 범위를 분류·추적했다는 것이 의료 정보의 정확성 검증이나 모든 복합 주장의 자동 분리까지 의미하지는 않습니다.

## 필수 Supabase SQL (순서)

이전에 002를 실행하지 않았다면 **002 다음에 003**을 순서대로 실행합니다.

1. `supabase/migrations/202610160002_complete_source_single_proposal.sql`: source_manifest 열 추가, 기존 선택 승인 함수의 12건 검사를 제거. 기존 001 위에 적용.
2. `supabase/migrations/202610160003_atomic_learning_proposals.sql`: 원본 보관 테이블과 **사실별 독립 변경안 생성 함수** 추가. 기존 지식/변경안/승인 기록은 변경하지 않습니다.

## 기술적 한계

**인위적인 사실 개수 제한 없음**은 무제한 처리 자원을 의미하지 않습니다. 입력 텍스트 최대 80,000자, 원문 추출본 합계 최대 200,000자, 지식 본문당 12,000자(DB 기존 제약)를 적용합니다. 너무 긴 단일 문장/문서나 DB 요청이 실패하면 해당 원문의 변경안을 일부만 만들지 않습니다. PDF 이미지/그림/표는 텍스트 추출로 누락될 수 있습니다. 환자 개인정보나 실제 의료 의사결정용 민감자료는 넣지 마세요.

SQL을 실행하지 않으면 서버가 안전하게 오류를 반환합니다. 이전 12건짜리 변경안은 자동 변경하지 않습니다.
